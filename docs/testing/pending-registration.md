# 待归属测试

本文件记录分支开发期间新增、但尚未找到稳定权威来源的测试选择器，
让开发者和 Review 能看见测试为何存在、合并前应如何处置。
权威来源可以是当前 `GR-xxx`、契约、ADR、测试与工程规则，
或由 Issue 记录的长期回归。
这类 Issue 必须写明缺陷、当前预期行为和长期防回归的必要性；
任意或仅记录历史的 Issue 不能单独成为权威来源。

登记时填写测试选择器和具体保护目的。合并前，每项必须且只能选择以下一种结果：

1. **提升为永久行为测试**：按当前预期行为命名测试，并链接到 GR、ADR、契约
   或其他长期规则。回归来源必须链接上述合格 Issue；来源是 GR 时，同时更新
   [GR 规则—测试追踪矩阵](requirements-traceability.md)。
2. **删除临时测试**：一次性迁移、搜索、探针、施工验证或仅保护已移除旧路径的测试
   应在同一 PR 删除，并在 PR 中保留验证证据。
3. **有条件保留**：仅当真实旧消费者或跨 PR 迁移依赖阻止删除时使用。
   移除待归属行前，必须把原行的准确测试选择器和保护目的转入具体清理 Issue；
   Issue 还须写明依赖、退出条件、受影响代码和测试、里程碑。
   PR 处置必须链接该 Issue；Issue 作为清理记录保留至退出条件满足。
   这是例外，不是默认处置；不得用含糊的后续 `chore` 代替。

Bug 回归不自动等于旧语义。保护当前预期行为的测试应提升并按行为命名，
不得命名为 `test_issue_123`；只保护已移除旧路径的测试应在替代证据形成后
于同一 PR 删除。面向预期永久行为的红色 TDD 测试也不是临时测试，
实现完成后必须提升并登记来源。

本文件和规则保留在 main，但 main 及最终合并状态的活动队列必须包含零条数据行。
当前不设置 CI 脚本或自动检查；Review 负责执行这一合并门禁。

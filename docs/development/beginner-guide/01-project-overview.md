# 第一章：项目与业务概览

## 1.1 项目解决什么问题

在传统计算集群中，用户通常需要自己准备代码和数据、编写作业脚本、选择资源、运行
`sbatch`、等待排队，再到不同目录查找日志和结果。这个流程很灵活，但对刚接触集群的学生
并不友好，也很难回答下面几个问题：

- 这次计算究竟使用了哪一版代码、数据和环境？
- 同组成员能否复用我的配置，而不是重新抄一遍命令？
- 运行失败发生在哪一步，日志和结果保存在哪里？
- 半年后还能否知道当时是怎样运行的？

107 Workspace 把这些步骤组织成浏览器中的协作工作流。用户在 Workspace 中管理成员和资源，
在 Project 中保存文件与版本，通过 Run Configuration 描述“想怎样运行”，提交后由平台创建
不可变的 Run Snapshot，再交给 Mock Scheduler 或 Slurm 执行。

平台并不会取代 Slurm。Slurm 仍然负责计算资源的排队和作业执行；107 Workspace 负责在它
之上组织用户、项目、配置、权限、可复现信息、日志和产物。

## 1.2 先记住八个概念

术语的完整定义在产品设计的统一领域语言中。刚开始开发时，先掌握下表即可。

| 概念 | 可以先这样理解 |
| --- | --- |
| User | 使用平台的人 |
| Workspace | 成员、项目和资源的协作与权限边界 |
| Project | 一项计算工作的代码、文件、版本和运行记录容器 |
| Project Version | 某个时刻发布的、不可原地修改的项目内容版本 |
| Run Configuration | 可编辑、可复用的运行方案 |
| Run Snapshot | 提交 Run 时固定下来的执行事实，创建后不可修改 |
| Run | 一次具体执行及其状态、日志和 Artifact |
| Artifact | 一次 Run 产生并由平台收集的结果文件 |

还有三组概念容易混淆：

- **Environment** 决定代码在什么软件基础上运行；**Shared Resource** 是 Run 可以读取的
  共享内容，例如数据集。
- **Compute Plan** 描述可选择的算力方案；**Resource Entitlement** 表示某个 Workspace
  获准使用哪些方案。
- **Variable** 是普通配置；**Secret** 是密码、Token 等不能明文展示或记录的敏感值。

代码标识符、数据库字段、接口字段和日志字段都应使用产品设计中的同一个英文术语。不要为了
“更顺口”自行创造同义词；如果确实出现新概念，应先更新领域术语，再写代码。

## 1.3 对象之间的关系

可以先用下面这张简图建立直觉：

```text
User ──加入──> Workspace
                 |
                 +──拥有──> Project ──发布──> Project Version
                 |             |
                 |             +──保存──> Run Configuration
                 |                            |
                 +──获得算力权益              +──提交──> Run
                                                      |
                                                      +──固定 Run Snapshot
                                                      +──产生日志和 Artifact
```

这不是完整数据模型，但足以帮助你查找大多数日常功能。看到一个资源 ID 时，首先要问它属于
哪个 Workspace；看到一个 Version 或 Snapshot 时，首先要问它是否允许更新。

## 1.4 三条必须守住的规则

### 权限边界

平台服务多个用户和 Workspace。只按资源 ID 查询，例如 `WHERE id = ?`，可能让用户通过
别人的 ID 访问不属于自己的数据。归属过滤必须落实到数据访问层，并且为“使用别人的 ID”
补充 403 或 404 测试。

开发身份模式使用 `X-User` 请求头，方便本地切换用户，但它不是生产认证方案。不要因为本地
能轻易切换身份，就把权限校验当成界面功能。

### 不可变性

Project Version、Environment Version、Shared Resource Version 和 Run Snapshot 等对象发布
或创建后不能原地修改。发生变化时应创建新版本或新的 Run，而不是覆盖历史。这样日志和结果
所引用的执行事实才不会随时间改变。

### Secret 不泄露

Run Snapshot、日志和页面都不能出现 Secret 明文。快照只保存引用表达式，执行时再由受控
边界解析。不要把真实 JWT、密码或本地 `.env` 提交到 Git。

## 1.5 当前已经有什么，仍缺什么

当前代码提供了可运行的 FastAPI 后端、React 控制台、数据库迁移、本地内容存储、Mock
Scheduler、Slurm REST Adapter、OpenAPI 契约和 Docker Compose 演示环境。

真实 Git 版本存储、Shared FS 验收、独立 Worker、Apptainer 准备链路、学校认证以及真实
107 Slurm 环境仍需要按产品设计中的 Milestone 实现或验证。因此：

- 本地 Mock 跑通，只能证明本地开发闭环可用；
- 代码中存在 Slurm Adapter，不等于已经完成真实集群接入；
- 产品设计中写出的能力，不一定已经进入当前代码。

阅读代码时把“当前实现”和“目标设计”分开，是参与这个项目的第一项基本能力。

# 风险、审阅重点与延期范围

本轮后端验收已经通过，但“测试通过”不等于所有运行环境风险都已消失。本文将
代码审阅优先级、剩余风险和明确延期范围放在一起，便于形成审阅结论。

## 2. 最高风险：Slurm 与 SSH

本地测试不需要真实集群，因此必须明确区分“逻辑合同已验证”和“目标环境已验证”。
建议审阅以下问题：

1. 所有本地命令是否始终通过参数数组启动，而不是 shell 字符串；
2. SSH host 是否只能来自服务端配置，不能来自 HTTP 请求；
3. 远程参数是否只在 SSH transport 处统一引用；
4. job ID、项目 URI、数据集 URI、metadata 和 artifact key 是否在命令执行前校验；
5. `squeue` 与 `sacct` 的状态是否完整、保守地映射到领域状态；
6. 取消是否保持幂等，终态作业是否不会再次 `scancel`；
7. tar writer/reader 任一失败或取消时，另一个进程是否被终止并回收；
8. 收集目录输出时是否拒绝越出运行工作目录或未声明输出。

部署前还需用真实集群验证 SSH host key、账号权限、Slurm 版本输出、路径可见性、
配额、超时、网络中断和大文件行为。

## 3. 运行一致性风险

运行提交流程刻意不在数据库事务中执行集群调用，避免长事务，但由此产生需要审阅
的失败窗口：

- 数据库已保存 snapshot，但外部 submit 失败；
- 外部作业已创建，但保存 external job ID 前进程中断；
- 用户取消与 submit 返回同时发生；
- reconciler 与 API 同时尝试更新状态；
- 终态日志或产物已写入存储，但数据库记录尚未提交。

当前实现使用稳定失败状态、late cancellation、CAS 更新、事件历史和幂等产物检查
处理这些情况。审阅时应确认每个分支都能收敛到可解释状态，并且重试不会重复提交
外部作业或重复收集产物。

## 4. 安全边界

已经实现的安全措施包括：

- 工作区角色和资源归属校验；
- 归档资源拒绝新操作；
- 路径必须位于配置根目录；
- 相对路径、符号链接、URI query/fragment 和换行符校验；
- sbatch directive、job name 和远程命令注入测试；
- 外部命令错误在 API 层使用清理后的公共描述；
- 内容寻址对象存储和下载授权。

仍需强调：`X-User-Id` 只是后端阶段的可信身份头。没有反向代理认证或签名验证时，
任何可以访问 API 的调用方都能伪造该头。生产部署前必须替换或保护这一边界。

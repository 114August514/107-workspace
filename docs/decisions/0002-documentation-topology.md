# 0002. 区分活动文档、参考材料与历史归档

- 状态：已接受
- 日期：2026-08-01

## 背景

仓库根目录同时放置产品设计、Git 教程和延后事项，`docs/` 又混合活动规范、外部材料、
已结束 journal，以及 2026-07 后端重建的规格、计划和审阅快照。旧规格仍标为
“Approved”，但其领域模型、测试数量和实现状态已经被 workspace107 迁移替换，容易
让协作者误判事实来源。

根目录还保留了只含两个变量的 `stack.mk`，以及只负责指向其他文件的 `docker/README.md`。
本地被忽略的 `hpc-helper/` 是无许可证的外部独立仓库，不是活动依赖。

## 决定

- 根目录只保留自动发现入口、仓库级配置和薄 `Makefile`；可执行部署编排放在
  `deploy/`，跨组件机器契约放在 `contracts/`，各服务自己的构建文件仍由服务目录维护。
- 产品设计与延后事项放在 `docs/product/`，Git 协作规范放在 `docs/contributing/`，
  部署说明放在 `docs/operations/`。
- `docs/journal/` 只保存进行中记录；完成或放弃的记录进入对应归档。
- `docs/references/` 只保留仍需核验的外部原始材料和来源记录。
- 生成的 OpenAPI 与其他跨组件机器契约不放入人工文档树，统一由 `contracts/` 管理。
- 旧后端规格、计划、审阅与派生说明从 HEAD 淘汰，由祖先提交 `374aa9f` 和
  `docs/archive/README.md` 提供取回入口，不在当前树复制第二份。
- `hpc-helper` 只记录固定上游提交和吸收边界，不复制源码或 Git 历史。
- `stack.mk` 的变量内联到 `Makefile`；删除无独立信息的容器占位说明。

本 ADR 只取代 ADR-0001 中“活动设计与 Git 指南位于根目录”的路径约定，不改变它对
迁移来源、实现选择或兼容边界的决定。

## 后果

- 好：根目录和活动文档树都只暴露当前入口，协作者不必判断多份规格谁有效。
- 好：历史过程仍可通过 Git 提交、tag 和归档索引复核，同时不会被全文搜索当作活动规则。
- 好：Windows 不再遇到正式 `TODO.md` 与本地 `todo.md` 的大小写冲突。
- 坏：旧链接和个人书签需要更新；查看淘汰过程材料需要使用归档索引或 `git show`。
- 限制：annotated tag 必须由维护者显式 push，远程协作者才能用 tag 名访问迁移前树。

## 重新评估的条件

- 文档规模增长到单个产品设计难以审阅，需要按稳定责任拆分而不是复制内容。
- 历史材料迁移到独立、长期可访问的文档站点或仓库，可以缩减本仓库归档索引。

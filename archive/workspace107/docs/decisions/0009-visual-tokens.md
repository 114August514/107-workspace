# ADR-0009 界面样式集中到令牌，视觉取向借鉴开发者工具

状态：已接受 · 阶段：M2 · 相关：ADR-0008（能力决定入口显不显示）

## 背景

M1 的前端是「能用」的：组件划分清楚，没有 CSS 文件，24 种 antd 组件覆盖了全部界面。
但它看起来像一个后台管理系统，而不像一个开发者每天要盯着的工具。

具体问题有两类。

**第一类是密度。** 首页三个列表，同样的六行数据要 1142px 才放得下：

```text
卡片 24px 内边距  ×  表格自己的边框和表头  =  同一条边界画了两遍
表格行高 48px                              一屏少看四五行
页面标题 24px                              比它下面要扫的内容还显眼
```

**第二类是样式散落。** 全项目 75 处行内 `style={{}}`。多数是 antd 的正常用法
（`<Input style={{ width: 200 }}`），但里面混着颜色和间距——
`#1e1e1e`、`rgba(255,255,255,0.75)`、`marginTop: 16`。
**这些值改不动**：没人知道一共有几处，换配色时总会漏掉几个，
而漏掉的那几个往往在不常打开的页面上。

## 决策

### 1. 视觉取向借鉴 GitHub 这类面向开发者的工具

不是因为好看，是因为**要解决的是同一个问题**：屏幕上要放很多条目
（文件、版本、运行记录），用户是来扫的，不是来欣赏的。

这个项目的领域模型本来就和 GitHub 高度同构——
Workspace/Project/Version/RunConfiguration/Run 对应
Organization/Repository/Commit/Workflow/WorkflowRun，
配置变量甚至直接用了 `${{ vars.X }}` 语法（见[领域语言](../domain/glossary.md)）。
概念对得上，界面形态自然也可以对。

落成三条：

```text
用边框分区，不用阴影      阴影让每个盒子都在「浮起来」，一屏放五个就很吵
密度优先                  行高和留白压紧，一屏能多看几行就少翻一页
颜色只用来表达状态        通篇近乎黑白，绿色红色一出现就是有事发生
```

**主按钮用绿色，链接和选中态用蓝色。** 一屏上蓝色可能有十几处，
绿色永远只有一个——「可点的东西」和「会改变数据的那个按钮」得是两件事。

### 2. 样式一律走 `theme.ts`，组件里不写死颜色

antd 的 token 系统就是为这件事准备的：改一个值全站跟着变。

```ts
// theme.ts —— 唯一定义处
export const colors = { border: '#d1d9e0', terminalBg: '#1e1e1e', ... }

// 组件里
<Footer style={{ borderTop: `1px solid ${colors.border}` }}>
```

**不引入 CSS 文件。** 开一个 `.css` 就等于开了一条绕过令牌的路，
之后的覆盖会越堆越多，而且和 token 互相打架。

行内 `style` 没有一概禁止——`<Input style={{ width: 200 }}` 这种局部尺寸
写在用它的地方最清楚。禁的是**颜色**，因为颜色是全局一致性问题。

### 3. 重复的布局收成组件

三个，都是从实际重复里提出来的，不是先设计好的：

| 组件 | 取代了什么 |
| :--- | :--- |
| `Stack` | 15 个文件里逐字重复的 `<Space direction="vertical" style={{ width: '100%' }}>` |
| `PageHeader` | 四个页面四种写法的「面包屑 + 标题 + 标签 + 操作」 |
| `ListCard` | `<Card>` 套 `<Table>` 时那圈没有信息量的 16px 白边 |

`ListCard` 的关键是 **body 内边距为 0**：表头直接贴着卡片标题栏，
两者共用一个底色，读起来是一整块。

### 4. 标识符一律等宽

ID、路径、命令、调度任务号走 `<Mono>`。这不是装饰——
等宽字体下 `run_0980` 和 `run_098O` 一眼能看出不一样，比例字体下看不出来。
**用户要拿这些串去和别处比对**：把 Run ID 报给助教、把调度任务号贴到集群命令里。

时间用 `<RelativeTime>`：默认「3 小时前」（适合扫），
悬停显示「2026-07-26 14:03:11」（适合排查）。

## 效果

同样的数据、同样的六行：

| | 改动前 | 改动后 |
| :--- | ---: | ---: |
| 首页总高 | 1142px | 927px |
| 表格行高 | 48px | 40px |
| 顶栏高 | 64px | 56px |
| 卡片边框 | `#f0f0f0`（几乎看不见） | `#d1d9e0`（看得见） |
| 卡片内边距 | 24px + 表格自己的 | 0 |
| 组件里写死的颜色 | 5 处 | 0 |

## 放弃的方案

**引入 Tailwind 或 CSS-in-JS。** 会出现两套样式系统：一套 antd token，
一套自己的类名，同一个间距值在两边各写一遍。antd 的 token 已经够用。

**照抄 GitHub 的品牌色和排版细节。** 借鉴的是密度和信息层次这些**做法**，
不是它的外观身份。这是学校的平台，不该让人以为是别人的产品。

**把行内 style 全部禁掉。** 试过这个方向，结果是为了 `width: 200`
去 theme 里加一个语义不明的 token。局部尺寸留在原地更清楚。

**先做深色模式。** antd 的 token 支持 `darkAlgorithm`，加起来不难，
但现在连浅色都还没定型，两套一起改会互相干扰。等这套稳定了再说。

## 守住它的测试

| 约定 | 测试 |
| :--- | :--- |
| 颜色只在 `theme.ts` 里定义 | `src/theme.test.ts::颜色只在 theme.ts 里定义` |
| 不出现 CSS 文件 | `src/theme.test.ts::没有 CSS 文件` |
| 主按钮和链接不同色 | `src/theme.test.ts::主按钮和链接不是同一个颜色` |
| 容器不用阴影 | `src/theme.test.ts::容器不用阴影` |
| 代码风格不被无意改掉 | CI 的 `format:check`（见 #17） |

第一条验证过会红：在 `RunPage.tsx` 里写一个 `#ff00ff`，测试立刻指名那个文件。
